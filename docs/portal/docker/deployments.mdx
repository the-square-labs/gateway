# Blue/green Deployments

A Deployment owns a stable application identity and two runtime slots. A release prepares the inactive slot, validates health, switches traffic, and retains the previous slot for rollback.

## Release checklist

1. Use an immutable image digest or approved build artifact.
2. Verify environment, secrets, volumes, GPU selection, and health route.
3. Deploy to the inactive slot.
4. Wait for health to pass.
5. Switch traffic.
6. Verify customer requests and logs.
7. Keep the previous slot until the rollback window expires.

Webhook-triggered releases still pass through authorization and health checks. If a release fails before cutover, the current slot remains active. If customer impact appears after cutover, use the explicit rollback action rather than editing the active child container.
