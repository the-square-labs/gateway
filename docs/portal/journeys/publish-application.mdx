# Publish an application end to end

This journey produces a public HTTPS application from a container image or Git source.

## 1. Prepare runtime capacity

Enroll a Docker node and an nginx node. Confirm both are online and have the required ports, storage, and runtime capabilities.

## 2. Create the workload

Choose a standalone Container for a simple service, a Deployment for health-checked blue/green rollout and rollback, or a Compose Project for a multi-service application. Configure image, command, environment, secrets, ports, restart policy, limits, and managed volumes.

## 3. Establish health

Select a published HTTP route for the workload health check. Configure path, expected status range, optional body match, timeout, interval, and slow threshold. Do not publish traffic until health is stable.

## 4. Register the domain and TLS

Add the Domain, place it on the nginx node, configure DNS, and issue or upload a certificate.

## 5. Create the Route

Select the managed workload as the upstream. Use a Secure Link where you do not want a normally published management path. Enable WebSockets or custom forwarding behavior only when the application needs it.

## 6. Verify

- public DNS and TLS;
- application health and logs;
- nginx access/error logs;
- restart and rollback behavior;
- least-privilege user access;
- notification delivery;
- backup coverage for stateful volumes and external dependencies.

## 7. Prepare rollback

For Deployments, verify the previous slot remains a valid rollback target. For image-based containers, record the immutable digest. For Git builds, keep the last approved artifact and deployed commit visible.
