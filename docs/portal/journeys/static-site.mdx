# Publish a static site with Pages

## Artifact upload path

1. Enable Pages in feature settings.
2. Create a Pages Project and select nginx placement.
3. Upload the built static artifact through the resumable deploy API or remote MCP upload workflow.
4. Finalize the immutable Deployment.
5. Move the system-managed `latest` Tag or a custom Tag to the Deployment.
6. Create a Pages Route for the public domain and selected Tag.
7. Verify caching, runtime configuration, and rollback by moving the Tag.

## Git build path

On supported plans, connect a repository, discover `package.json`, select the package manager and build command, configure Build Secrets, and publish the approved artifact to the requested Tag.

## Runtime configuration

Pages can serve public runtime configuration from `/_gateway/pages/config.js` as `window.runtime.config`. It is public, capped at 64 KiB, and served with `no-store`. Never place secrets in it.

## Rollback

Move the Route's Tag back to a known-good immutable Deployment. Do not mutate the old artifact in place.
