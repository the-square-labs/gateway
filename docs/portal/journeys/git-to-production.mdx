# Git to production

Git-backed delivery is available where the current plan entitlement permits it.

## Happy path

1. Configure a GitLab, GitHub, generic Git, or External SSH integration under **Settings > Integrations**.
2. Enroll a dedicated Build Worker and verify its capabilities.
3. Create or open a Container, Deployment, Compose Project, or Pages Project.
4. Select Repository mode and choose repository, branch, build context, and Dockerfile or Compose file.
5. Add source-scoped Build Secrets. They are exposed as BuildKit secret mounts, not ordinary build arguments.
6. Queue a build and inspect source resolution, worker assignment, logs, vulnerability results, and policy outcome.
7. Deploy only an approved immutable digest.
8. Verify health and the deployed commit.

## Compose behavior

A repository Compose build can create one child build per service. The rollout proceeds only after every expected artifact is approved. A failed, rejected, cancelled, or superseded child prevents publication of the revision.

## Safety checks

- Pin deployment by digest, not a mutable tag.
- Keep automatic build and automatic deploy as separate decisions.
- Do not place credentials in repository URLs, build arguments, or logs.
- Treat the Build Worker host as disposable and isolated.
- Confirm downgrade or entitlement loss behavior before depending on unattended delivery.
