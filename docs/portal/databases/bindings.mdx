# Application database bindings

A binding targets a standalone Container, Deployment, or Compose service. Gateway creates a dedicated database user or role and delivers connection settings through the managed connector path.

The binding lifecycle is designed to satisfy three properties:

1. engine ownership remains with Gateway's managed owner identity;
2. every application receives a separate least-privilege identity;
3. recreate, restart, and reconciliation do not create orphan roles.

After creating a binding, apply the workload update and verify an application query. Inspect runtime telemetry and both workload and database logs. During a Relay or node restart, desired state remains durable and should reconcile automatically.

Delete the binding through Gateway. Manual role deletion can desynchronize durable state and should be reserved for an explicit recovery procedure.
