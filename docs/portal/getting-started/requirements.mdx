# Requirements and planning

Plan the control plane separately from managed workload hosts.

## Gateway host

Use a supported Linux host with Docker Engine and Docker Compose. Reserve persistent storage for PostgreSQL, uploaded artifacts, certificates, configuration, and optional structured logs. The exact capacity depends on retention, Pages artifacts, build volume, and activity history; production installations should monitor disk growth and back up both data and encryption keys.

The public installation requires:

- a stable canonical URL;
- inbound HTTP/HTTPS for the web application;
- inbound `9443/tcp` to the Relay when managed nodes connect over the public network;
- correct system time and working DNS;
- outbound access to configured identity, ACME, source-control, registry, update, and AI providers.

## Node roles

Choose only the roles you need:

- **nginx node:** ingress, TLS materialization, Pages, logs, and metrics;
- **Docker node:** containers, Deployments, Compose, files, logs, and runtime health;
- **database node:** managed PostgreSQL, Redis, or ClickHouse instances;
- **Build Worker:** isolated BuildKit/containerd execution without a Docker Engine socket;
- **monitoring node:** monitoring-specific collection;
- **Relay Pool member:** optional data-plane resilience and capacity.

Do not place Build Workers on hosts containing unrelated workloads or reusable credentials. Treat their outer VM or unprivileged container as the security boundary.

## DNS and certificates

Decide whether Gateway will manage DNS through Cloudflare or only validate externally managed records. HTTP-01 requires public port 80 on the assigned ingress node. DNS-01 requires a configured DNS provider integration.

## Production decisions to make first

1. Canonical public URL and TLS termination model.
2. Authentication methods and first administrator ownership.
3. Backup destination and recovery owner.
4. Node role separation and firewall policy.
5. Domain/DNS operating model.
6. Required plan entitlements.
7. Logging retention and SIEM requirements.
8. Whether Git builds require dedicated Build Workers.

See [Ports and network](../reference/ports-and-network.mdx) before changing firewalls.
