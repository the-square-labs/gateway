# Initial setup

The setup wizard establishes the first administrator and instance-wide security settings. Complete it from the canonical Gateway URL.

<!-- screenshot: id=setup-wizard-auth; viewport=1440x900; description=Setup wizard authentication-method step; redact=domain,email,provider-client-id -->

## Happy path

1. Enter the installer-provided setup code.
2. Confirm the public URL and network settings.
3. Configure at least one authentication method: OIDC, local password, or email one-time code.
4. Create the first administrator.
5. Configure MFA when required by policy.
6. Review feature settings and complete setup.
7. Sign in through the normal login page and store recovery material securely.

## Authentication choices

- **OIDC:** recommended when an organization already operates an identity provider. Redirect URIs must match exactly.
- **Local password:** useful for self-contained installations and break-glass access. Apply strong password and MFA policy.
- **Email one-time code:** requires working outbound email configuration before it can be relied on.
- **Passkeys:** enrolled after the primary account exists and used as an MFA-capable authentication factor.

Gateway does not implement SCIM. Do not plan provisioning or deprovisioning around a nonexistent SCIM connector.

## After setup

- Create a second administrative recovery path.
- Verify **Profile > Authorizations** and revoke any bootstrap session no longer needed.
- Configure backups and test that encrypted secrets can be restored with the preserved master key.
- Create least-privilege groups before onboarding ordinary users.
- Add the first managed node.

If setup fails, confirm the code is still valid, the canonical URL is correct, migrations completed, and the browser reaches the same origin used by Gateway cookies.
